# 使用者確認用設計說明

本 skill 僅限使用者明確觸發，不依需求內容自動選用。

根據本次需求與已有上下文，建立 `<feature>-srs.md`，放在使用者指定或專案既有文件位置。若關鍵功能尚未確定且會影響敘述，精確詢問；不編造操作細節。

- 開頭以白話交代需求背景與文件面向，讓使用者快速理解。
- 使用 User／UI 的語言，以功能與操作流程組織即將實作的內容，描述入口、操作與使用者看見的結果。
- 不列待使用者核可資訊；使用者已有自己的確認流程。
- 不寫雙方決策過程，除非該內容已聲明為使用者確認事項。
- 不加入測試清單。
- 不額外明列因邊界而不處理的項目，沿用原 command 的功能導向呈現；不隱瞞會讓已描述流程失真的重要事實。

完成後讀回文件，核對需求、使用者用語、流程及 `-srs.md` 檔名，回覆實際可點擊路徑與必要限制。內容準備供確認，不代表已獲准實作、commit 或發布；檔案操作依實際 shell 的路徑與編碼方式，使用 UTF-8。

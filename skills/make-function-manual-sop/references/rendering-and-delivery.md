# 渲染 QA 與交付

需要 DOCX／PDF 或進行最終 QA／交付時讀取。工具選擇依執行環境，不指定 Word COM、特定 renderer 或固定腳本。

## 能力確認

先確認環境可用的文件產製與渲染工具、版本、輸入／輸出能力及可寫的暫存位置。依目標格式選擇能保留版面的工具；例如 Word、LibreOffice 或 runtime 提供的渲染服務只是候選，不是必要依賴。針對候選做 bounded capability probe；一個工具不可用只排除該工具，不代表所有候選都不可用。

只有本次成功輸出才是 render evidence。記錄實際 renderer、版本、命令／工具、來源文件版本、輸出 PDF／逐頁影像、頁數、結果與錯誤；可使用 JSON 或既有工具的 evidence 格式，不要求某個未提供的 `render-evidence.json` schema。執行後讀回證據，不能以 spawn、檔名或舊輸出推定成功。

## 結構與視覺檢查

- 文件可開啟，圖片均內嵌，版本、日期、URL、圖號與欄位名稱一致。
- 清除未完成的製作占位、工具 token、帳密與未遮罩敏感資訊；待系統／業務確認的規則如實標示，不編造。
- 逐頁以可讀比例檢查裁切、表格溢位、中文缺字、紅框與編號、頁首頁尾及分頁。
- 宣稱「Word 視覺渲染」須有本次實際 Word 成功輸出與檢視證據；其他工具以其真實名稱回報。成功產製檔案但尚未檢視，不等於視覺 QA 完成。

## 受限與回退

Probe 成功而 render 失敗時，保留實際錯誤及 evidence，再選可用且符合需求的替代方案。只有本次啟動且具有 identity／ownership 證據的程序可安全收尾；不關閉使用者既有 Word 或其他程序。暫存路徑或執行檔問題先依環境修正，不將工具失敗當成文件通過。

所有 renderer 都不可用時仍可做結構檢查、或在可用情況人工開啟檢視。交付必須明確寫「已完成結構檢查；未完成渲染 QA，原因為…」，並保留缺少的必要驗證；不可宣稱版面無誤。

## 交付

將最終檔複製到約定位置，確認存在、非零大小與合理修改時間；對 DOCX／PDF 比對來源與目標 SHA-256，或至少大小。以可點擊路徑回報涵蓋功能、版本依據、實際 renderer、完成的檢查與未解限制。原始截圖與內部 QA 產物留在工作紀錄，只有使用者要求時交付。
